## Generator and conventions

The forecast convention is positive: `xhat_t = a[0]*x[t-1] + ... + a[p-1]*x[t-p]`. AR polynomial coefficients are therefore `[1, -a1, ..., -ap]`. The companion matrix has `a` in its first row and identity on the subdiagonal; stability means its eigenvalues are inside the unit disk.

`DataConfig()` fixes one AR(4) regime, scalar observations, independent N(0,1) innovations, 200 discarded steps and exactly 10,000 retained steps. The first `SeedSequence(seed).spawn(2)` child draws four independent standard Gaussian coefficients; the second draws innovations, using independent PCG64 streams. Coefficients are fixed for the entire simulation. Four pre-simulation lags are zero. The finite burn-in approximates stationary initialization; it is not an exact draw from the stationary initial distribution.

For original radius rho, choose `s = min(1, 0.9*(1-1e-12)/rho)` and set **lag-k coefficient to `s**k * a_k`**. Substitution into the characteristic polynomial gives `P_new(z) = s**4 P_old(z/s)`, so every eigenvalue becomes `s` times its original value. This establishes the radius bound; a fresh eigensolve verifies it. A Gaussian draw already below the cap is unchanged. Scaling every coefficient by the same constant would not establish this property. `ground_truth.json` saves the original draw, transformed coefficients, scale, original/final radii, seed/configuration and raw innovation variance. None of this enters `OnlineARExperts` or `run_stream`.

## Covariances and Levinson–Durbin

For standardized observations z, store, for k=0,...,L:

```text
r_t(k) = lambda*r_(t-1)(k) + (1-lambda)*z_t*z_(t-k).
```

The default **lambda=0.99 is an implementation choice**, not a value prescribed by the assignment, and was not tuned on these results. The assignment's effective memory convention gives `1/(1-lambda)=100`. The relative loading `epsilon=1e-6`, variance floor `1e-12`, and reflection margin `1e-10` are implementation choices too.

The scalar assignment rule loads a working copy only: `c(0) = r(0)*(1+epsilon)` and `c(k)=r(k)` otherwise. Stored `r` is never loaded or replaced with `c`. At order p solve `T_p a_p = [c(1),...,c(p)]`, with `T_p[i,j]=c(abs(i-j))`. The dense reference uses `np.linalg.solve`, the same `r`, and the same epsilon.

Starting with v0=c(0), the recursion computes:

```text
kappa_p = (c(p) - dot(a_(p-1), [c(p-1),...,c(1)])) / v_(p-1)
a_p[:p-1] = old_a - kappa_p*reverse(old_a)
a_p[p-1] = kappa_p
v_p = v_(p-1)*(1-kappa_p**2)
```

`old_a` is copied before revision. One pass produces all coefficients and model prediction-error variances in O(L^2) work. An order is accepted only if the preceding and updated variances are finite and greater than the floor, and `abs(kappa_p) < 1-reflection_margin`. This is the scalar positive-definiteness/Schur-stability guard.

At the first failed order **p and every higher order**, both coefficients and variances retain their previous-time values; lower valid orders update normally. This deliberately applies the user's conservative policy to the failing expert itself as well as to higher experts. Recursion stops immediately. Before the first successful fit, the fallback is zero coefficients and unit standardized prior variances, explicitly stale. There is no clipping, silent retry, adaptive loading or zeroing of previously fitted experts. Stale variances are not Schur complements of the current covariances. `fresh`, consecutive `stale_steps`, first failed order/reason, attempted reflections and total guard count expose this distinction.

Independent lagged EW products need not form a positive-definite Toeplitz sequence on every finite sample, especially with short memory; the guard handles that. Within one valid recursion variances decrease algebraically. A displayed curve mixing stale and fresh orders need not decrease.

## Causal initialization and update order

`initialize` takes exactly the first `5L=40` retained raw observations. Compute their mean and population standard deviation (`ddof=0`), then freeze both. If the standard deviation is at most `1e-12`, use scale 1 and flag `constant_warmup`. The floor is configurable. The zero-variance case produces centered zeros and uses the documented stale fallback until enough usable covariance arrives.

Start covariance estimates at zero and replay standardized warm-up values through the EW update, filling a newest-first L-lag history. Unavailable lags before retained observation zero are treated as zero standardized values: their products are zero while all stored covariance entries continue to decay. No generated burn-in observations enter initialization. There is no EW weight/bias correction or division by lag-specific sample counts. Fit once after all warm-up values are ingested; no warm-up forecasts are scored. Reusing the whole warm-up block to standardize that same initialization block is permitted: all 40 values have arrived before the first evaluated forecast.

At each evaluated zero-based index t=40,...,9999:

1. Call `predict()` and save the returned forecasts and pre-observation state.
2. Let Tasnuba's gate combine them using only earlier errors/features.
3. Reveal the raw target, transform it with the frozen normalization, and record errors using the saved forecasts.
4. Call `update(raw_target)`: update covariances/history and refit experts for target t+1.
5. Update the gate/backbone using the saved pre-observation forecasts, features and weights, following the assignment's gate timing.

The example exposes hooks for steps 2 and 5 and implements no gate or weighting baseline. Full-series means, quantiles and ACF are calculated only for descriptive diagnostics after the forecasts are formed; they cannot affect preprocessing.

## Tasnuba's interface and units

```python
from ar_experts import OnlineARExperts

experts = OnlineARExperts().initialize(warmup_raw)  # (40,) or (40,1)
forecasts_z = experts.predict()                   # (8,1), AR(1)..AR(8)
before = experts.snapshot()                      # independent copies
# mixture_z = your_gate.predict(forecasts_z, features_from_the_past)
# Observe target_raw only after the prediction above.
target_z = experts.standardize(target_raw)
expert_squared_errors_z = (target_z - forecasts_z)**2
forecasts_raw = experts.inverse_transform(forecasts_z)
experts.update(target_raw)                        # raw scalar, (1,), or (1,1)
# your_gate.update(...saved pre-observation inputs...)
```

`predict()` has no side effects; repeated calls before update are identical. It returns **standardized** forecasts; `update` consumes **raw** observations. Keep target shape `(1,)` or `(1,1)` when subtracting `(8,1)` forecasts. To obtain a vector `(8,)` of errors, use `(float(target_z.item()) - forecasts_z[:, 0])**2`. `stream_with_gate` in `AR4/ar_experts/example.py` is a runnable integration example on the actual required 10,000-point series; its optional callbacks document the two handoff points.

Snapshot fields include coefficients `(L,L)` (row p-1, columns 0..p-1, zero padding), model error variances `(L,)`, standardized/raw error covariances `(L,1,1)`, stored and working lag covariances `(L+1,)`, newest-first standardized history `(L,)`, frozen normalization, configuration, observation count/next target index, and diagnostics. Arrays/dictionaries returned by `snapshot()` are independent copies. Modifying them cannot change the experts. Forecasts are newly allocated arrays too.

The saved NPZ arrays are indexed by **forecast target**, using `target_indices`. Forecasts and squared errors are `(9960,L,1)`, targets `(9960,1)`, coefficient paths `(9960,L,L)`, covariance paths `(9960,L+1)`, and fresh/stale/reflection arrays `(9960,L)`. Stored coefficient/variance states are from **before** that target is observed; final post-series state is intentionally not assigned to a nonexistent scored target. Total guard counts in the summary include the final update, which may differ from the count of scored pre-target states.

Raw noise variance is 1; standardized innovation variance is **1/scale^2**, generally not 1. Raw squared errors/variances equal standardized values times `scale^2`. Normalization is estimated from only 40 samples: frozen centering can leave a nonzero mean, so finite-sample coefficient paths need not center exactly on the generating coefficients. There is no separately fitted intercept; de-standardization induces the raw intercept `mean*(1-sum(a))`.

## Verification and diagnostic interpretation

The 17 tests cover independent state-space Lyapunov population covariances for white noise, AR(1) with both coefficient signs, and a stable nontrivial AR(4); every-order agreement with dense Yule–Walker with and without loading; population variance flattening at order four; lag order and signs; failing-order/higher-order retention; zero/nonfinite covariance guards; exact burn-in and innovation alignment; reproducibility and radius scaling; missing-lag initialization; loading not accumulating; constant warm-up and input validation; configurable L; snapshot/predict purity; and causality under changes to current/future targets.

Stochastic sanity checks use seeds 685, 686, 687 and a broad post-startup forecast-loss bound, not an exact coefficient/ranking expectation. Tight deterministic tolerances are approximately 1e-12 (or tighter for analytic cases). Online tests allow 2e-10; the full diagnostic run checks every valid order at every scored state against the dense solver, with an absolute 1e-9 ceiling, and records actual maximum differences. These tolerances are for well-conditioned checks, not a general condition-number guarantee.

| Output | What it checks | What would indicate a problem |
|---|---|---|
| `summary.json` | Exactly 10,000 retained/9,960 scored, finite values, distribution, truth radius <=0.9, frozen scaling | Wrong length, nonfinite values/forecasts, changing preprocessing, radius above cap |
| `data_diagnostics` | Raw trace and lag dependence | Exploding scale, obvious regime changes in this fixed regime, unexpected alignment or missing observations; random excursions alone do not prove a bug |
| `coefficient_paths` | Lag-1..4 estimates from AR(4)..AR(8) against fixed truth | Persistent large discrepancy calls for checking lag/sign conventions, centering bias, memory and guards; small fluctuations are expected |
| `variance_by_order` | Fresh-only recent mean/temporal SD, latest model variance, realized raw MSE, standardized/raw noise scales | Nonpositive fresh variance, wrong units, or broad failure to reduce underfitting; no exact finite-sample plateau is required |
| `alignment_and_guards` | First 160 scored targets/AR(4) forecasts, first failed order, stale mask | A shifted target curve, failures without stale flags, or long periods dominated by stale estimates; spikes should be investigated |
| Dense comparisons and spectral radii | All valid orders solve the same equations; all retained expert polynomials remain stable | Differences above tolerance or unstable accepted experts |

The last-2,000-step variance bars describe temporal fluctuations, **not confidence intervals**. Fixed forgetting preserves estimation noise indefinitely. Larger orders can lower the fitted model variance while worsening realized forecast MSE. AR(4) is not required to win every realization. A zero guard count on benign stationary data is fine; deliberate invalid updates in tests verify the failure path. The runner's dense solves, snapshots, and eigenvalue diagnostics intentionally add overhead; the actual expert fit remains O(L^2).

## Known limits

This only implements n=1. No gate history is filled during warm-up because no gate is implemented; Tasnuba owns that initialization. Normalization stays frozen for this milestone and may be unsuitable after regime changes. Short warm-up and fixed memory create bias/noise; diagonal loading introduces a small deliberate regularization bias. Consecutive stale counts measure fit passes (one at warm-up, then one per update). A high stale fraction means the retained experts may be uninformative even if forecasts are finite. The synthetic burn-in is finite. Three-seed summaries are sanity checks, not the final tuned experimental study or evidence that a learned mixture improves prediction.
